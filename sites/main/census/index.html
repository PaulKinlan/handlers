Integration census: every way a web app can be opened

Port Authority is about what two pages can do once they hold a port to each other. This page is about the step before that: how a web app gets opened in the first place. A link with a scheme of its own, a file double-clicked in the operating system, a share from another app, an icon on the home screen, a message to a service worker.

Each row below is checked in the browser you are reading this with, when the page loads. A green bar means the browser has it. A red bar means it is missing or was refused. Nothing on this page asks you for anything until you press a button.

How this page was opened

This page is also an installable app. Its manifest declares a handler for web+census: links, for .txt and .census files, a share target and a launch handler. Every route ends up here, and this list records what arrived. Install the page, then open it each way from Try each route.

  1. Opened as an ordinary page, with nothing handed to it.

Links with a scheme of their own

A page can ask to receive every link that starts with a given scheme with registerProtocolHandler. An installed app can declare the same in its manifest with protocol_handlers. In both cases the handler is given the whole link as one string in its address. My earlier post Detecting if a URL scheme can be handled is about what happens when nothing handles it.

Files

With file_handlers in its manifest, an installed app appears in the operating system's Open with list for the file types it names. The files arrive on launchQueue as handles, which can be written back to. launch_handler decides whether each launch opens a new window or goes to one already open.

Sharing

navigator.share sends text, a link or files out through the system share sheet. share_target in a manifest puts an installed app into that sheet. On this page the share arrives at the service worker as a form, which keeps it and sends the window here. I wrote about registering as a share target and receiving files when they first shipped.

How this census was made

Every check is in probes.js, the buttons and the launch list in launches.js, and the service worker in sw.js. A check that finds a function only says it is there. It does not prove that the browser shows it to people, which on some platforms it does not. The routes that need an installed app are only proved by trying them.

I have run it in Chromium on Linux only so far, in a tab and not installed. The gaps it finds are written up, with what each would let people build, on What is missing. If a row is wrong in your browser, please open an issue.
